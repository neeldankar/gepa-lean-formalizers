# Pitfalls that previously caused failures — avoid them

**(P1) The ambient group/space is a TYPE, not a subobject.**
With `{G : Type*} [Group G]`, the identifier `G` is a type. Writing `K ≤ G`, `H.relindex G`, `H.index G`, etc. fails: there is no `LE (Type _)` instance, and these functions expect a `Subgroup G`. The whole group viewed as a subgroup of itself is `⊤ : Subgroup G`. Hence:
- the index `|G : H|` is `H.relindex ⊤` (or `H.index`);
- an assumption "`K ≤ G`" is vacuous — drop it (or write `K ≤ ⊤`);
- the same pattern applies to `Submodule R M`, `Ideal R`, etc.: the ambient structure is `⊤`.
Also recall `H.relindex K` is the index of `H` in `K`, i.e. `|K : H|`. Do NOT add finiteness assumptions the problem doesn't have (`relindex`/`index` are `0` for infinite index, so results like the chain rule hold in `ℕ` without `Fintype G`).

# Method

1. Read the problem and list: (a) the objects and their types, (b) every hypothesis/assumption, (c) the exact conclusion, (d) the **logical structure** — is it "for all …, if … then …", or "there exists a counterexample" (watch for "does not need to be", "not necessarily", "may fail to be")?
2. Map each object to a Lean/Mathlib type using the context (e.g. subgroup → `Subgroup G`, prime → `Nat.Prime p`, rational number → `ℚ`, the ring ℤ[√d] → `Zsqrtd d`, a family of sets indexed by α → an index-type binder plus `T : ι → Set (Set X)`).
3. **Before writing each expression, recall the EXACT Mathlib signature of every function, predicate and notation you use**: how many explicit arguments, in what order, of what types. Most compile failures come from guessing signatures (e.g. `DifferentiableOn f s` is wrong — the scalar field is the first explicit argument: `DifferentiableOn ℝ f s`). If you are unsure whether an identifier exists (`IsSquarefree`? `f'`?), use the standard one you are sure of (`Squarefree`, `deriv f`).
4. Write the theorem with one binder per variable/hypothesis and the conclusion as the target. If the problem defines an auxiliary object by a formula (e.g. `g(x) = f(x)/x`), inline it as a lambda (`fun x => f x / x`) in the conclusion, or bind `(g : ℝ → ℝ)` with a defining hypothesis `(hg : ∀ x, g x = f x / x)`.

6. Re-read the original problem and verify the statement says *exactly* that.

# Pitfalls that previously caused failures — avoid them

**(P1) The ambient group/space is a TYPE, not a subobject.**
With `{G : Type*} [Group G]`, the identifier `G` is a type. Writing `K ≤ G`, `H.relindex G`, `H.index G`, etc. fails: there is no `LE (Type _)` instance, and these functions expect a `Subgroup G`. The whole group viewed as a subgroup of itself is `⊤ : Subgroup G`. Hence:
- the index `|G : H|` is `H.relindex ⊤` (or `H.index`);
- an assumption "`K ≤ G`" is vacuous — drop it (or write `K ≤ ⊤`);
- the same pattern applies to `Submodule R M`, `Ideal R`, etc.: the ambient structure is `⊤`.
Also recall `H.relindex K` is the index of `H` in `K`, i.e. `|K : H|`. Do NOT add finiteness assumptions the problem doesn't have (`relindex`/`index` are `0` for infinite index, so results like the chain rule hold in `ℕ` without `Fintype G`).
Correct formalization of "H ≤ K ≤ G ⇒ |G:H| = |G:K|·|K:H|":
```lean4
theorem Lagrange_chain_rule {G : Type*} [Group G] (H K : Subgroup G) (hHK : H ≤ K) :
    H.relindex ⊤ = K.relindex ⊤ * H.relindex K := by sorry
```

**(P2) Parenthesize products inside conjugation (multiplication is left-associative).**
`g⁻¹ * a * g` parses as `(g⁻¹ * a) * g` — it conjugates `a` alone. "ab is conjugate to ba" must be written:
```lean4
theorem ab_conj_ba {G : Type*} [Group G] (a b : G) :
    ∃ g : G, g⁻¹ * (a * b) * g = b * a := by sorry
```
or equivalently `IsConj (a * b) (b * a)` (Mathlib's `IsConj a b` is defined as `∃ c : G, c * a * c⁻¹ = b`). A compiling statement that conjugates the wrong term is judged unfaithful.

**(P3) Big-operator syntax and index sets.**
`∑ i in s, f i` / `∏ i in s, f i` require `open scoped BigOperators` (present in the context when sums appear). If in doubt, use `Finset.sum s (fun i => f i)`, which always parses. Match the index set exactly: `1 + 1/2 + … + 1/(p-1)` is a sum over `Finset.Icc 1 (p - 1)` (or over `Finset.range (p - 1)` with term `1 / ((i : ℚ) + 1)`), NOT over `Finset.range p` (which starts at `i = 0`).

**(P4) Division and coercions.**
With `a b : ℤ`, the expression `a / b` is INTEGER division. A rational fraction is `(a : ℚ) / (b : ℚ)`. Write casts explicitly: `(i : ℚ)`, `(p : ℤ)`. For divisibility of an integer by a natural prime, write `(p : ℤ) ∣ a`.

**(P5) Keep every hypothesis; use the right quantifier structure.**
"Let p be an odd prime" requires BOTH `(hp : Nat.Prime p)` and `(hodd : Odd p)` (or `hp2 : p ≠ 2`). "… = a/b, where a, b are integers. Show p ∣ a" means: bind `a b : ℤ` universally together with the hypothesis that the sum equals `(a : ℚ) / b`, and conclude `(p : ℤ) ∣ a`:
```lean4
theorem p_divides_a (p : ℕ) (hp : Nat.Prime p) (hodd : Odd p) (a b : ℤ)
    (h : (∑ i in Finset.Icc 1 (p - 1), (1 : ℚ) / (i : ℚ)) = (a : ℚ) / (b : ℚ)) :
    (p : ℤ) ∣ a := by sorry
```
Do not wrap the whole statement in an existential unless the problem asserts existence.

**(P6) Respect the signatures of definitions given in the context.**
If the context defines e.g. `Subgroup.relindex (H K : Subgroup G) : ℕ`, its arguments are subgroups — pass `⊤` for the whole group, never the type `G` itself. Likewise, if the context defines `is_topology (X : Type*) (T : Set (Set X))`, call it as `is_topology X s` where `s : Set (Set X)`.

**(P7) The ring ℤ[√d] is `Zsqrtd d`; `√` is the REAL square root; the squarefree predicate is `Squarefree`.**
- There is no `IsSquarefree` in Mathlib — the predicate is `Squarefree` (e.g. `(hsq : Squarefree n)` for `n : ℕ`).
- The ring ℤ[√d] (for `d : ℤ`, possibly negative) is `Zsqrtd d`, with notation `ℤ√d`. Its parameter is a `ℤ`, so with `n : ℕ` write `ℤ√(-(n : ℤ))`. Elements are pairs `⟨a, b⟩` meaning `a + b√d`; the element `√d` itself is `Zsqrtd.sqrtd` (i.e. `⟨0, 1⟩`); integers embed via the usual casts, so `2` and `1 + Zsqrtd.sqrtd` are the elements `2` and `1 + √d`. `Zsqrtd d` is a `CommRing` for any `d : ℤ`, so `Irreducible` applies to its elements.
- The prefix notation `√` is `Real.sqrt` — it acts on real numbers and does NOT construct quadratic rings. `ℤ[√-n]` is not valid Lean.
Correct formalization of "2, √-n and 1+√-n are irreducible in ℤ[√-n]":
```lean4
theorem irreducibles_in_Zsqrtd (n : ℕ) (hn : 3 < n) (hsq : Squarefree n) :
    Irreducible (2 : ℤ√(-(n : ℤ))) ∧
    Irreducible (Zsqrtd.sqrtd : ℤ√(-(n : ℤ))) ∧
    Irreducible (1 + Zsqrtd.sqrtd : ℤ√(-(n : ℤ))) := by sorry
```

**(P8) Parenthesize the argument of prefix notation when it is negative or composite.**
`√-n` fails with "unexpected token at this precedence level; consider parenthesizing the term" — write `√(-n)`. The same applies whenever a prefix operator is followed by a unary minus or a composite term: when in doubt, parenthesize.

**(P9) A family of sets is a FUNCTION from an index type.**
`Set α` is defined as `α → Prop`. So if `T : Set (Set X)` and you write `T i`, that application has type `Prop`, not `Set (Set X)` — a type error ("has type Prop … but is expected to have type Set (Set X)"). A family `𝒯_α` of sets of sets needs an index-type binder and a function:
```lean4
(ι : Type*) (T : ι → Set (Set X))
```
Then `T i : Set (Set X)` and `⋃ i, T i : Set (Set X)` (the `⋃` notation is `Set.iUnion`, available with `open Set`). The same applies to any indexed family: `H : ι → Subgroup G`, `s : ι → Set X`, etc.

**(P10) "Show that P does not need to hold" / "P may fail" / "not necessarily P" = exhibit a counterexample.**
The faithful formalization is an EXISTENCE statement (equivalently, the negation of the universal one):
```lean4
theorem union_of_topologies_not_topology :
    ∃ (X : Type*) (ι : Type*) (T : ι → Set (Set X)),
      (∀ i, is_topology X (T i)) ∧ ¬ is_topology X (⋃ i, T i) := by sorry
```
(`∃ X : Type*` is fine in a theorem; Lean auto-binds the universe variables.) Do NOT write `∀ …, (hypotheses) → ¬ (conclusion)` — that claims P NEVER holds, which is the opposite of "P does not need to hold" and is usually false. Conversely, do not weaken a universal problem into an existential.

**(P11) Analysis: the scalar field is an explicit argument, the derivative is `deriv f`, and domain restrictions use the `…On` predicates.**
- `DifferentiableOn`, `DifferentiableAt`, `Differentiable`, `HasDerivAt`, `fderiv` take the scalar field as the FIRST explicit argument: `DifferentiableOn ℝ f s`, `DifferentiableAt ℝ f x`. Writing `DifferentiableOn f s` passes `f` as the field and fails with a confusing "expected type Type" error. (`ContinuousOn f s` has no field argument.)
- There is no `f'` notation in Lean. The derivative of `f : ℝ → ℝ` is the function `deriv f : ℝ → ℝ` (its value at `x` is `deriv f x`). "f′(x) exists for x ∈ s" is `DifferentiableOn ℝ f s` (or `∀ x ∈ s, DifferentiableAt ℝ f x`).
- Match the stated domain with the `…On` predicates and the right set: `x ≥ 0` → `Set.Ici 0`, `x > 0` → `Set.Ioi 0`; continuity on a domain → `ContinuousOn f s`; monotonicity on a domain → `MonotoneOn g s`. Do NOT strengthen `MonotoneOn g (Set.Ioi 0)` to `Monotone g` when the function is only defined/considered for `x > 0` — that changes the claim.
Correct formalization of "f continuous on x ≥ 0, f′ exists for x > 0, f(0) = 0, f′ increasing ⇒ g(x) = f(x)/x increasing on x > 0":
```lean4
theorem g_monotone (f : ℝ → ℝ)
    (hf_cont : ContinuousOn f (Set.Ici 0))
    (hf_diff : DifferentiableOn ℝ f (Set.Ioi 0))
    (hf0 : f 0 = 0)
    (hderiv_mono : MonotoneOn (deriv f) (Set.Ioi 0)) :
    MonotoneOn (fun x => f x / x) (Set.Ioi 0) := by sorry
```

Topology:

- "homeomorphism" → `X ≃ₜ Y`.

Group theory:
- "the order of an element x" (|x| = n) → `orderOf x = n` (`orderOf : G → ℕ`; it is `0` for infinite order). NOT `x ^ n = 1` and NOT an invented `order x`.
- "a is conjugate to b" → `IsConj a b` (defined as `∃ c : G, c * a * c⁻¹ = b`).

Number theory / algebra:

- "x is a unit" → `IsUnit x`; "minimal polynomial" → `minpoly R x`.

# Pitfalls that previously caused failures — avoid them

**(P1) The ambient group/space is a TYPE, not a subobject.**
With `{G : Type*} [Group G]`, the identifier `G` is a type. Writing `K ≤ G`, `H.relindex G`, `H.index G`, etc. fails: there is no `LE (Type _)` instance, and these functions expect a `Subgroup G`. The whole group viewed as a subgroup of itself is `⊤ : Subgroup G`. Hence:
- the index `|G : H|` is `H.relindex ⊤` (or `H.index`);
- an assumption "`K ≤ G`" is vacuous — drop it (or write `K ≤ ⊤`);
- the same pattern applies to `Submodule R M`, `Ideal R`, etc.: the ambient structure is `⊤`.
Also recall `H.relindex K` is the index of `H` in `K`, i.e. `|K : H|`. Do NOT add finiteness assumptions the problem doesn't have (`relindex`/`index` are `0` for infinite index, so results like the chain rule hold in `ℕ` without `Fintype G`).
Correct formalization of "H ≤ K ≤ G ⇒ |G:H| = |G:K|·|K:H|":
```lean4
theorem Lagrange_chain_rule {G : Type*} [Group G] (H K : Subgroup G) (hHK : H ≤ K) :
    H.relindex ⊤ = K.relindex ⊤ * H.relindex K := by sorry
```

**(P2) Parenthesize products inside conjugation (multiplication is left-associative).**
`g⁻¹ * a * g` parses as `(g⁻¹ * a) * g` — it conjugates `a` alone. "ab is conjugate to ba" must be written:
```lean4
theorem ab_conj_ba {G : Type*} [Group G] (a b : G) :
    ∃ g : G, g⁻¹ * (a * b) * g = b * a := by sorry
```
or equivalently `IsConj (a * b) (b * a)`. A compiling statement that conjugates the wrong term is judged unfaithful.

**(P3) Big-operator syntax and index sets.**
`∑ i in s, f i` / `∏ i in s, f i` require `open scoped BigOperators` (present in the context when sums appear). If in doubt, use `Finset.sum s (fun i => f i)`, which always parses. Match the index set exactly: `1 + 1/2 + … + 1/(p-1)` is a sum over `Finset.Icc 1 (p - 1)` (or over `Finset.range (p - 1)` with term `1 / ((i : ℚ) + 1)`), NOT over `Finset.range p` (which starts at `i = 0`).

**(P4) Division and coercions.**
With `a b : ℤ`, the expression `a / b` is INTEGER division. A rational fraction is `(a : ℚ) / (b : ℚ)`. Write casts explicitly: `(i : ℚ)`, `(p : ℤ)`. For divisibility of an integer by a natural prime, write `(p : ℤ) ∣ a`.

**(P5) Keep every hypothesis; use the right quantifier structure.**
"Let p be an odd prime" requires BOTH `(hp : Nat.Prime p)` and `(hodd : Odd p)` (or `hp2 : p ≠ 2`). "… = a/b, where a, b are integers. Show p ∣ a" means: bind `a b : ℤ` universally together with the hypothesis that the sum equals `(a : ℚ) / b`, and conclude `(p : ℤ) ∣ a`:
```lean4
theorem p_divides_a (p : ℕ) (hp : Nat.Prime p) (hodd : Odd p) (a b : ℤ)
    (h : (∑ i in Finset.Icc 1 (p - 1), (1 : ℚ) / (i : ℚ)) = (a : ℚ) / (b : ℚ)) :
    (p : ℤ) ∣ a := by sorry
```
Do not wrap the whole statement in an existential unless the problem asserts existence.

**(P6) Respect the signatures of definitions given in the context.**
If the context defines e.g. `Subgroup.relindex (H K : Subgroup G) : ℕ`, its arguments are subgroups — pass `⊤` for the whole group, never the type `G` itself.

**(P7) Use exact Mathlib identifier names — capitalization matters.**
`Connected` and `Interior` do NOT exist; the correct names are `IsConnected` and `interior`. Because `autoImplicit` is false, an unknown identifier is a compile error (score 0), not an implicit variable. Before writing each notion, recall its spelling from the reference table; follow the `IsX`-for-predicates / lowercase-for-operations convention.

**(P8) "It is not true in general that P ⇒ Q" is a NEGATED UNIVERSAL (or a counterexample), not a universal with a negated conclusion.**
"Show that if S is connected, it is not true in general that its interior is connected" must be formalized as:
```lean4
theorem interior_not_connected_in_general :
    ¬ ∀ S : Set ℝ, IsConnected S → IsConnected (interior S) := by sorry
```
or equivalently `∃ S : Set ℝ, IsConnected S ∧ ¬ IsConnected (interior S)`. Writing `(S : Set ℝ) (hS : IsConnected S) ⊢ ¬ IsConnected (interior S)` claims EVERY connected set has disconnected interior — a different, much stronger (and false) statement → unfaithful.

**(P9) "Positive integer n" needs an explicit positivity binder.**
`n : ℕ` alone allows `n = 0`. Add `(hn : 0 < n)` (or use `n : ℕ+`). The same goes for "nonzero" (`hx : x ≠ 0`), "n ≥ 2" (`(hn : 2 ≤ n)`), "odd prime" (both `Nat.Prime p` and `Odd p`). Dropping a side condition is unfaithful even when the statement compiles. Correct formalization of "for any integers a,b,c there exists a positive integer n such that √(n³+an²+bn+c) is not an integer":
```lean4
theorem exists_pos_n_sqrt_not_int (a b c : ℤ) :
    ∃ n : ℕ, 0 < n ∧ ¬ ∃ k : ℤ, k ^ 2 = (n : ℤ) ^ 3 + a * (n : ℤ) ^ 2 + b * n + c := by sorry
```
Note the `∀ a b c` (theorem binders) then `∃ n` with positivity INSIDE the existential via `∧`.

**(P10) Named notions carry their full definition — do not weaken them to one property.**
"|x| = n" (the ORDER of a group element) is `orderOf x = n`, NOT `x ^ n = 1`: the latter says only that n is *some* exponent killing x, dropping minimality; and with `n = 0` it would even trivialize. Keep the positivity side condition too. Correct formalization of "if |x| = n for some positive integer n then x⁻¹ = xⁿ⁻¹":
```lean4
theorem inv_eq_pow_order_sub_one {G : Type*} [Group G] (x : G) (n : ℕ) (hn : 0 < n)
    (hx : orderOf x = n) : x⁻¹ = x ^ (n - 1) := by sorry
```
The same principle applies to any "least/smallest" notion: minimal polynomial (`minpoly`), order of a group (`Nat.card G` / `Fintype.card G`), degree, rank — use the dedicated Mathlib definition.

**(P11) Preserve the problem's quantifier order and the placement of negation.**
"For any … there exists … such that …" → universal binders, then an existential target carrying ALL the stated properties. "There exists … such that for all …" → existential outside, universal inside. "Show that P does not imply Q" → `¬ (∀ …, P → Q)` or `∃ …, P ∧ ¬ Q` (see P8). Swapping ∀/∃ or moving a negation changes the meaning → unfaithful.

Topology:

Group theory:

- "measurable set / function" → `MeasurableSet S` / `Measurable f`.

With `a b : ℤ`, `a / b` is INTEGER division; a rational fraction is `(a : ℚ) / (b : ℚ)`. Write casts explicitly: `(i : ℚ)`, `(p : ℤ)`, `(r : ℂ)`, `(N : ℤ)`.

**(P5) Keep every hypothesis; use the right quantifier structure.**
"Let p be an odd prime" requires BOTH `(hp : Nat.Prime p)` and `(hodd : Odd p)`. "… = a/b, where a, b are integers. Show p ∣ a" means: bind `a b : ℤ` universally with the hypothesis that the sum equals `(a : ℚ) / b`, conclude `(p : ℤ) ∣ a`:
```lean4

```

**(P6) Respect the signatures of definitions given in the context.**
If the context defines e.g. `Subgroup.relindex (H K : Subgroup G) : ℕ`, pass `⊤` for the whole group, never the type `G` itself. Likewise, a context `local notation` fixes the exact type of its argument — match it.

**(P7) Use exact Mathlib identifier names — capitalization matters.**

**(P10) Named notions carry their full definition — do not weaken them to one property.**
"|x| = n" (the ORDER of a group element) is `orderOf x = n`, NOT `x ^ n = 1`:

**(P11) Preserve the problem's quantifier order and the placement of negation.**
"For any … there exists …" → universal binders, then an existential target carrying ALL stated properties. "There exists … such that for all …" → existential outside, universal inside. "Show P does not imply Q" → `¬ (∀ …, P → Q)` or `∃ …, P ∧ ¬ Q`.

**(P12) `λ` is not Lean 4.** Anonymous functions are `fun n => a n + b n`. A real failure wrote `limsup (λ n, (a n + b n))` → parse error → score 0.

**(P13) Bind every symbol the problem names, and formalize every "where"-clause as a hypothesis binder.**
If the problem says "if M₁ ≡ M^d (mod N) … where d′ satisfies d d′ ≡ 1 (mod φ(N))", then `M₁` and `d'` are binders AND `(hdd' : d * d' ≡ 1 [MOD Nat.totient N])` is a hypothesis. Leaving `M₁` free is an unknown-identifier error; dropping the `d d' ≡ 1` condition is unfaithful.

**(P14) Number-type discipline for `Nat.*` functions.**

**(P15) Prefer `r : ℝ` + `(hr : 0 ≤ r)` over `r : ℝ≥0` when r appears in mixed-type arithmetic**, and always write casts explicitly: `(r : ℂ) * w`, never bare `r * w` across types.

**(P16) Match context-notation types exactly, and translate side conditions correctly.**
If the context's `local notation "limsup"` is defined for `u : ℕ → EReal`, the binders must be `(a b : ℕ → EReal)`. - "x is a unit" → `IsUnit x`; "minimal polynomial" → `minpoly R x`.

- **Real / imaginary part → `Complex.re z` / `Complex.im z` (or `z.re` / `z.im`). `Re` / `Im` do NOT exist** (a real failure used `Im (f z)` → unknown identifier → score 0).
- **Complex absolute value / modulus → `Complex.abs w` or `‖w‖`. NOT `Complex.norm`, NOT `(w : ℂ).norm`.**
- **"f is holomorphic on an open set Ω" → bind `(Ω : Set ℂ)` `(hΩ : IsOpen Ω)` and `(hf : DifferentiableOn ℂ f Ω)`.** Do not weaken to `ContinuousOn`; do not replace `Ω` with `Set.univ`.
- **"f is constant (on S)" → there is NO `ConstantOn` in Mathlib.** Write `∃ c, ∀ z ∈ S, f z = c` (or `∀ z ∈ S, ∀ w ∈ S, f z = f w`). "Im(f) is constant on Ω" → `∃ c : ℝ, ∀ z ∈ Ω, (f z).im = c`.

Analysis / sets:
- "square root" → `Real.sqrt x` (after `open Real`, just `sqrt x`); "exp/log/sin/cos" → `Real.exp` / `Real.log` / `Real.sin` / `Real.cos`.
- **Nonnegative reals: the type `ℝ≥0` (= `NNReal`) exists, but mixing it into arithmetic with `ℝ`/`ℂ` often fails to unify or coerce. PREFER `r : ℝ` with a `(hr : 0 ≤ r)` binder and explicit casts, e.g. `z = (r : ℂ) * w`.**
- **Extended reals → `EReal`; +∞ is `⊤`, −∞ is `⊥`. "The sum is not of the form ∞ − ∞" → `¬ ((x = ⊤ ∧ y = ⊥) ∨ (x = ⊥ ∧ y = ⊤))` — it excludes BOTH mixed cases, NOT `x = ⊤ ∧ y = ⊤`.**
- "limsup / liminf" → `Filter.limsup u atTop` / `Filter.liminf u atTop` (needs `open Filter`); if the context supplies a `local notation "limsup"`, use it with arguments of exactly the declared type.
- "derivative" → `deriv f x` / `HasDerivAt f f' x`; "differentiable" → `Differentiable ℝ f`; "differentiable on a set" → `DifferentiableOn ℝ f S` (over ℂ: `DifferentiableOn ℂ f S`).
- "interval integral" → `∫ x in a..b, f x`.
- "sum/product over a finite set" → `∑ x in s, f x` / `∏ x in s, f x` (needs `open scoped BigOperators`) or `Finset.sum s f` / `Finset.prod s f` (always parses).
- "finite set" → `s : Finset α`; cardinality → `s.card`; "fintype" → `Fintype α` with `Fintype.card α`; "finite type" → `Finite α`.
- intervals: `Finset.Icc a b`, `Finset.range n` (= {0,…,n-1}), `Set.Icc a b`, `Set.Ioo a b`.
- "supremum / infimum of a set" → `sSup S` / `sInf S`.
- "measurable set / function" → `MeasurableSet S` / `Measurable f`.
- reals/complex/rationals/integers → `ℝ` / `ℂ` / `ℚ` / `ℤ`; nonnegative reals → `ℝ≥0`; extended nonnegative reals → `ℝ≥0∞`.
- absolute value → `|x|`; norm → `‖x‖`.

If unsure of a name, prefer the standard Mathlib spelling above and fully qualify it (e.g. `Set.IsConnected`). NEVER emit a name you are not certain exists — if no certain name exists for a notion, expand the notion into quantifiers over names you do know (see Method step 4).

# Pitfalls that previously caused failures — avoid them

**(P1) The ambient group/space is a TYPE, not a subobject.**
With `{G : Type*} [Group G]`, writing `K ≤ G` or `H.relindex G` fails. The whole group as a subgroup is `⊤ : Subgroup G`; the index `|G : H|` is `H.relindex ⊤` (or `H.index`); `H.relindex K` means `|K : H|`. Same pattern for `Submodule R M`, `Ideal R`. Do NOT add finiteness assumptions the problem doesn't have. Correct formalization of "H ≤ K ≤ G ⇒ |G:H| = |G:K|·|K:H|":
```lean4
theorem Lagrange_chain_rule {G : Type*} [Group G] (H K : Subgroup G) (hHK : H ≤ K) :
    H.relindex ⊤ = K.relindex ⊤ * H.relindex K := by sorry
```

**(P2) Parenthesize products inside conjugation (multiplication is left-associative).**
`g⁻¹ * a * g` conjugates `a` alone. "ab is conjugate to ba":
```lean4
theorem ab_conj_ba {G : Type*} [Group G] (a b : G) :
    ∃ g : G, g⁻¹ * (a * b) * g = b * a := by sorry
```
or equivalently `IsConj (a * b) (b * a)`.

**(P3) Big-operator syntax and index sets.**
`∑ i in s, f i` needs `open scoped BigOperators`; if in doubt use `Finset.sum s (fun i => f i)`. Match the index set exactly: `1 + 1/2 + … + 1/(p-1)` is over `Finset.Icc 1 (p - 1)`, NOT `Finset.range p`. For set-valued families, `⋃ i, U i` / `⋂ i, C i` are the indexed operators — `∪`/`∩` are binary only (see P17).

**(P4) Division and coercions.**
With `a b : ℤ`, `a / b` is INTEGER division; a rational fraction is `(a : ℚ) / (b : ℚ)`. Write casts explicitly: `(i : ℚ)`, `(p : ℤ)`, `(r : ℂ)`, `(N : ℤ)`.

**(P5) Keep every hypothesis; use the right quantifier structure.**
"Let p be an odd prime" requires BOTH `(hp : Nat.Prime p)` and `(hodd : Odd p)`. "… = a/b, where a, b are integers. Show p ∣ a" means: bind `a b : ℤ` universally with the hypothesis that the sum equals `(a : ℚ) / b`, conclude `(p : ℤ) ∣ a`:
```lean4
theorem p_divides_a (p : ℕ) (hp : Nat.Prime p) (hodd : Odd p) (a b : ℤ)
    (h : (∑ i in Finset.Icc 1 (p - 1), (1 : ℚ) / (i : ℚ)) = (a : ℚ) / (b : ℚ)) :
    (p : ℤ) ∣ a := by sorry
```
Do not wrap the whole statement in an existential unless the problem asserts existence.

**(P6) Respect the signatures of definitions given in the context.**
If the context defines e.g. `Subgroup.relindex (H K : Subgroup G) : ℕ`, pass `⊤` for the whole group, never the type `G` itself. Likewise, a context `local notation` fixes the exact type of its argument — match it. If the context defines a custom predicate (e.g. `countably_compact X`), apply it exactly as declared.

**(P7) Use exact Mathlib identifier names — capitalization matters.**
`Connected`, `Interior`, `Nat.phi`, `Complex.norm`, `Im`, `Re`, `ConstantOn` do NOT exist; the correct names are `IsConnected`, `interior`, `Nat.totient`, `Complex.abs` / `‖·‖`, `Complex.im`, `Complex.re`, and an explicit `∃ c, ∀ z ∈ S, f z = c`. With `autoImplicit` off, an unknown identifier is a compile error (score 0).

**(P8) "It is not true in general that P ⇒ Q" is a NEGATED UNIVERSAL (or a counterexample), not a universal with a negated conclusion.**
```lean4
theorem interior_not_connected_in_general :
    ¬ ∀ S : Set ℝ, IsConnected S → IsConnected (interior S) := by sorry
```
or equivalently `∃ S : Set ℝ, IsConnected S ∧ ¬ IsConnected (interior S)`.

**(P9) "Positive integer n" needs an explicit positivity binder.**
Add `(hn : 0 < n)` (or use `n : ℕ+`). Same for "nonzero" (`hx : x ≠ 0`), "n ≥ 2" (`(hn : 2 ≤ n)`), "odd prime" (both `Nat.Prime p` and `Odd p`):
```lean4
theorem exists_pos_n_sqrt_not_int (a b c : ℤ) :
    ∃ n : ℕ, 0 < n ∧ ¬ ∃ k : ℤ, k ^ 2 = (n : ℤ) ^ 3 + a * (n : ℤ) ^ 2 + b * n + c := by sorry
```

**(P10) Named notions carry their full definition — but literal equations stay literal.**
"|x| = n" (the ORDER of a group element) is `orderOf x = n`, NOT `x ^ n = 1`:
```lean4
theorem inv_eq_pow_order_sub_one {G : Type*} [Group G] (x : G) (n : ℕ) (hn : 0 < n)
    (hx : orderOf x = n) : x⁻¹ = x ^ (n - 1) := by sorry
```
Conversely, "there is a positive integer n such that aⁿ = e" is literally `∃ n : ℕ, 0 < n ∧ a ^ n = 1` — do NOT "upgrade" it to `orderOf`. Same for minimal polynomial (`minpoly`), group order (`Nat.card G` / `Fintype.card G`), degree, rank, totient (`Nat.totient`): use the dedicated definition exactly when the problem names the notion.

**(P11) Preserve the problem's quantifier order and the placement of negation.**
"For any … there exists …" → universal binders, then an existential target carrying ALL stated properties. "There exists … such that for all …" → existential outside, universal inside. "Show P does not imply Q" → `¬ (∀ …, P → Q)` or `∃ …, P ∧ ¬ Q`.

**(P12) `λ` is not Lean 4.** Anonymous functions are `fun n => a n + b n`. A real failure wrote `limsup (λ n, (a n + b n))` → parse error → score 0.

**(P13) Bind every symbol the problem names, and formalize every "where"-clause as a hypothesis binder.**
If the problem says "if M₁ ≡ M^d (mod N) … where d′ satisfies d d′ ≡ 1 (mod φ(N))", then `M₁` and `d'` are binders AND `(hdd' : d * d' ≡ 1 [MOD Nat.totient N])` is a hypothesis. Leaving `M₁` free is an unknown-identifier error; dropping the `d d' ≡ 1` condition is unfaithful.

**(P14) Number-type discipline for `Nat.*` functions.**
`Nat.Coprime`, `Nat.totient`, `Nat.gcd`, `Nat.lcm`, `Nat.choose`, `Nat.factorial` take ℕ only. Either keep the variables in ℕ, or switch the notion (`IsCoprime` for ℤ) — never pass an ℤ to `Nat.Coprime`.

**(P15) Prefer `r : ℝ` + `(hr : 0 ≤ r)` over `r : ℝ≥0` when r appears in mixed-type arithmetic**, and always write casts explicitly: `(r : ℂ) * w`, never bare `r * w` across types.

**(P16) Match context-notation types exactly, and translate side conditions correctly.**
If the context's `local notation "limsup"` is defined for `u : ℕ → EReal`, the binders must be `(a b : ℕ → EReal)`. And "provided the sum is not of the form ∞ − ∞" means excluding the two mixed cases `(⊤, ⊥)` and `(⊥, ⊤)` — writing `¬ (limsup a = ⊤ ∧ limsup b = ⊤)` excludes the wrong thing and is unfaithful.

**(P17) Indexed union/intersection are the BIG operators `⋃`/`⋂`; `∪`/`∩` are binary infix only.**
A real failure wrote `(∩ i, C i) ≠ ∅` → parse error `unexpected token '∩'; expected ')', ...` → score 0. Write `(⋂ i, C i) ≠ ∅` or `(⋂ i, C i).Nonempty` (note the parentheses around the big operator). If the context's `def` already uses `⋃ i, U i`, mirror that shape with the dual symbol `⋂`.

**(P18) Complex parts are lowercase: `Complex.re` / `Complex.im`.**
A real failure wrote `Im (f z)` → unknown identifier → score 0. Write `(f z).im` or `Complex.im (f z)`. "Im(f) is constant on Ω" → `∃ c : ℝ, ∀ z ∈ Ω, (f z).im = c`.

**(P19) There is no `ConstantOn`; expand "constant" into quantifiers, and keep the problem's exact domain and hypothesis strength.**
A real failure wrote `ConstantOn f (Set.univ : Set ℂ)` → unknown identifier → score 0, and it also silently replaced "holomorphic on an open set Ω" with "continuous on univ" — doubly unfaithful. "f is constant on S" → `∃ c, ∀ z ∈ S, f z = c`. Keep `Ω` as a binder with `(hΩ : IsOpen Ω)`; keep "holomorphic" as `DifferentiableOn ℂ f Ω`.

**(P20) Do not weaken, strengthen, or relocate the problem's conditions.**
Every hypothesis keeps its stated strength (holomorphic ≠ continuous; connected ≠ path-connected) and its stated domain (an open set Ω ≠ univ; a subgroup H ≠ ⊤). Dropping or downgrading a hypothesis may still compile but scores 0 at the faithfulness stage.

# Grading

Two stages: (1) a Lean compilation check, then (2) a faithfulness judgment against the original problem. A statement that compiles but says something different scores 0, as does any statement with a syntax/type error.

# Method

0. **Inventory every symbol.** List each symbol/letter in the problem statement (dimension `k`, prime `p`, imaginary unit `i`, indices, …). Each one must become either (a) a binder you introduce, or (b) an exact Mathlib constant you are certain exists. There is no third option.

# Mathlib identifier reference — use these exact spellings

Topology / metric spaces:
- "S is connected" → `IsConnected S` (full name `Set.IsConnected`; available after `open Set`). NOT `Connected S` — that identifier does not exist.
- "interior / closure / frontier of S" → `interior S` / `closure S` / `frontier S` (all lowercase). NOT `Interior S`, NOT `Closure S` — capitalized versions do not exist.
- "S is open / closed / compact" → `IsOpen S` / `IsClosed S` / `IsCompact S`.
- "f is continuous / continuous at x" → `Continuous f` / `ContinuousAt f x`.
- "f is uniformly continuous" → `UniformContinuous f`.
- "Y is complete" (metric/uniform space) → instance binder `[CompleteSpace Y]`.
- "ball / closed ball / sphere" → `Metric.ball x r` / `Metric.closedBall x r` / `Metric.sphere x r` (available after `open Metric`).
- "neighborhood of x" → `𝓝 x` (needs `open scoped Topology`) or `nhds x`.
- "f tends to L" → `Tendsto f atTop (𝓝 L)` (needs `open Filter` for `atTop`).
- "uniform convergence" → `TendstoUniformly F f atTop`.
- "homeomorphism" → `X ≃ₜ Y`.
- "there exists a unique" → `∃! x, P x`.
- A set `S : Set X` coerces to a type `↥S` (its subtype); `closure A → Y` means functions out of the subtype `↥(closure A)`. `subset_closure : s ⊆ closure s` (root namespace).

Group theory:
- "the order of an element x" (|x| = n) → `orderOf x = n` (`orderOf : G → ℕ`; it is `0` for infinite order). NOT `x ^ n = 1` and NOT an invented `order x`.
- "a is conjugate to b" → `IsConj a b` (defined as `∃ c : G, c * a * c⁻¹ = b`).
- "G is cyclic" → `IsCyclic G`; "subgroup generated by S" → `Subgroup.closure S`.
- "group homomorphism" → `G →* H`; its kernel/range → `f.ker` / `f.range`.
- "group isomorphism" → `G ≃* H`; ring isomorphism → `R ≃+* S`; linear equivalence → `M ≃ₗ[R] N`.
- index of H in the whole group → `H.relindex ⊤` or `H.index` (see P1).

Number theory / algebra:
- "p is prime" (natural) → `Nat.Prime p`; (in a general ring) → `Prime p`.
- "even / odd" → `Even n` / `Odd n`; "coprime" → `Nat.Coprime m n`.
- "a divides b" → `a ∣ b` (typed `\|`); integer divided by a natural prime → `(p : ℤ) ∣ a`.
- "integers mod n" → `ZMod n`; "n choose k" → `Nat.choose n k` (or `n.choose k`); "n!" → `Nat.factorial n`.
- "gcd / lcm of naturals" → `Nat.gcd` / `Nat.lcm`.
- "Gaussian integers ℤ[i]" → `GaussianInt` (the notation `ℤ[i]` is also available after `import Mathlib`). "The imaginary unit i in ℤ[i]" → `GaussianInt.i`. The token `𝕚` does NOT exist — never use it. (For ℂ, the imaginary unit is `Complex.I`, available as `I` after `open Complex`.)
- "polynomial over R" → `Polynomial R` (notation `R[X]` needs `open Polynomial`).
- "matrix" → `Matrix m n R`; "rank / finite rank" → `Module.rank R M` / `FiniteDimensional.finrank R M`.
- "x is a unit" → `IsUnit x`; "minimal polynomial" → `minpoly R x`.

Analysis / sets:
- "Euclidean space ℝ^k" → `EuclideanSpace ℝ (Fin k)` with `(k : ℕ)` introduced as a binder. The notation `ℝ^k` does NOT exist in Lean. Norm on it: `‖x‖`.
- "square root" → `Real.sqrt x` (after `open Real`, just `sqrt x`); "exp/log/sin/cos" → `Real.exp` / `Real.log` / `Real.sin` / `Real.cos`.
- "derivative" → `deriv f x` / `HasDerivAt f f' x`; "differentiable" → `Differentiable ℝ f`.
- "interval integral" → `∫ x in a..b, f x`.
- "sum/product over a finite set" → `∑ x in s, f x` / `∏ x in s, f x` (needs `open scoped BigOperators`) or `Finset.sum s f` / `Finset.prod s f` (always parses).
- "finite set" → `s : Finset α`; its cardinality → `s.card`; "fintype" → `Fintype α` with `Fintype.card α`; "finite type" → `Finite α`.
- intervals: `Finset.Icc a b`, `Finset.range n` (= {0,…,n-1}), `Set.Icc a b`, `Set.Ioo a b`.
- "supremum / infimum of a set" → `sSup S` / `sInf S`; "limsup/liminf" → `limsup` / `liminf` (after `open Filter`).
- "measurable set / function" → `MeasurableSet S` / `Measurable f`.
- reals/complex/rationals/integers → `ℝ` / `ℂ` / `ℚ` / `ℤ`; nonnegative reals → `ℝ≥0`; extended nonnegative reals → `ℝ≥0∞`.
- absolute value → `|x|`; norm → `‖x‖`.

If unsure of a name, prefer the standard Mathlib spelling above and fully qualify it (e.g. `Set.IsConnected`, `GaussianInt.i`). NEVER emit a name you are not certain exists.

# Pitfalls that previously caused failures — avoid them

**(P1) The ambient group/space is a TYPE, not a subobject.**
With `{G : Type*} [Group G]`, the identifier `G` is a type. Writing `K ≤ G`, `H.relindex G`, `H.index G`, etc. fails: there is no `LE (Type _)` instance, and these functions expect a `Subgroup G`. The whole group viewed as a subgroup of itself is `⊤ : Subgroup G`. Hence:
- the index `|G : H|` is `H.relindex ⊤` (or `H.index`);
- an assumption "`K ≤ G`" is vacuous — drop it (or write `K ≤ ⊤`);
- the same pattern applies to `Submodule R M`, `Ideal R`, etc.: the ambient structure is `⊤`.
Also recall `H.relindex K` is the index of `H` in `K`, i.e. `|K : H|`. Do NOT add finiteness assumptions the problem doesn't have (`relindex`/`index` are `0` for infinite index, so results like the chain rule hold in `ℕ` without `Fintype G`).
Correct formalization of "H ≤ K ≤ G ⇒ |G:H| = |G:K|·|K:H|":
```lean4
theorem Lagrange_chain_rule {G : Type*} [Group G] (H K : Subgroup G) (hHK : H ≤ K) :
    H.relindex ⊤ = K.relindex ⊤ * H.relindex K := by sorry
```

**(P2) Parenthesize products inside conjugation (multiplication is left-associative).**
`g⁻¹ * a * g` parses as `(g⁻¹ * a) * g` — it conjugates `a` alone. "ab is conjugate to ba" must be written:
```lean4
theorem ab_conj_ba {G : Type*} [Group G] (a b : G) :
    ∃ g : G, g⁻¹ * (a * b) * g = b * a := by sorry
```
or equivalently `IsConj (a * b) (b * a)`. A compiling statement that conjugates the wrong term is judged unfaithful.

**(P3) Big-operator syntax and index sets.**
`∑ i in s, f i` / `∏ i in s, f i` require `open scoped BigOperators` (present in the context when sums appear). If in doubt, use `Finset.sum s (fun i => f i)`, which always parses. Match the index set exactly: `1 + 1/2 + … + 1/(p-1)` is a sum over `Finset.Icc 1 (p - 1)` (or over `Finset.range (p - 1)` with term `1 / ((i : ℚ) + 1)`), NOT over `Finset.range p` (which starts at `i = 0`).

**(P4) Division and coercions.**
With `a b : ℤ`, the expression `a / b` is INTEGER division. A rational fraction is `(a : ℚ) / (b : ℚ)`. Write casts explicitly: `(i : ℚ)`, `(p : ℤ)`. For divisibility of an integer by a natural prime, write `(p : ℤ) ∣ a`. Likewise, numerals in a special ring need explicit type ascription, e.g. `(2 : GaussianInt)`.

**(P5) Keep every hypothesis; use the right quantifier structure.**
"Let p be an odd prime" requires BOTH `(hp : Nat.Prime p)` and `(hodd : Odd p)` (or `hp2 : p ≠ 2`). "… = a/b, where a, b are integers. Show p ∣ a" means: bind `a b : ℤ` universally together with the hypothesis that the sum equals `(a : ℚ) / b`, and conclude `(p : ℤ) ∣ a`:
```lean4
theorem p_divides_a (p : ℕ) (hp : Nat.Prime p) (hodd : Odd p) (a b : ℤ)
    (h : (∑ i in Finset.Icc 1 (p - 1), (1 : ℚ) / (i : ℚ)) = (a : ℚ) / (b : ℚ)) :
    (p : ℤ) ∣ a := by sorry
```
Do not wrap the whole statement in an existential unless the problem asserts existence.

**(P6) Respect the signatures of definitions given in the context.**
If the context defines e.g. `Subgroup.relindex (H K : Subgroup G) : ℕ`, its arguments are subgroups — pass `⊤` for the whole group, never the type `G` itself.

**(P7) Use exact Mathlib identifier names — capitalization matters.**
`Connected`, `Interior` and `Closure` do NOT exist; the correct names are `IsConnected`, `interior`, `closure`. Because `autoImplicit` is false, an unknown identifier is a compile error (score 0), not an implicit variable. Before writing each notion, recall its spelling from the reference table; follow the `IsX`-for-predicates / lowercase-for-operations convention.

**(P8) "It is not true in general that P ⇒ Q" is a NEGATED UNIVERSAL (or a counterexample), not a universal with a negated conclusion.**
"Show that if S is connected, it is not true in general that its interior is connected" must be formalized as:
```lean4
theorem interior_not_connected_in_general :
    ¬ ∀ S : Set ℝ, IsConnected S → IsConnected (interior S) := by sorry
```
or equivalently `∃ S : Set ℝ, IsConnected S ∧ ¬ IsConnected (interior S)`. Writing `(S : Set ℝ) (hS : IsConnected S) ⊢ ¬ IsConnected (interior S)` claims EVERY connected set has disconnected interior — a different, much stronger (and false) statement → unfaithful.

**(P9) "Positive integer n" needs an explicit positivity binder.**
`n : ℕ` alone allows `n = 0`. Add `(hn : 0 < n)` (or use `n : ℕ+`). The same goes for "nonzero" (`hx : x ≠ 0`), "n ≥ 2" (`(hn : 2 ≤ n)`), "odd prime" (both `Nat.Prime p` and `Odd p`). Dropping a side condition is unfaithful even when the statement compiles. Correct formalization of "for any integers a,b,c there exists a positive integer n such that √(n³+an²+bn+c) is not an integer":
```lean4
theorem exists_pos_n_sqrt_not_int (a b c : ℤ) :
    ∃ n : ℕ, 0 < n ∧ ¬ ∃ k : ℤ, k ^ 2 = (n : ℤ) ^ 3 + a * (n : ℤ) ^ 2 + b * n + c := by sorry
```
Note the `∀ a b c` (theorem binders) then `∃ n` with positivity INSIDE the existential via `∧`.

**(P10) Named notions carry their full definition — do not weaken them to one property.**
"|x| = n" (the ORDER of a group element) is `orderOf x = n`, NOT `x ^ n = 1`: the latter says only that n is *some* exponent killing x, dropping minimality; and with `n = 0` it would even trivialize. Keep the positivity side condition too. Correct formalization of "if |x| = n for some positive integer n then x⁻¹ = xⁿ⁻¹":
```lean4
theorem inv_eq_pow_order_sub_one {G : Type*} [Group G] (x : G) (n : ℕ) (hn : 0 < n)
    (hx : orderOf x = n) : x⁻¹ = x ^ (n - 1) := by sorry
```
The same principle applies to any "least/smallest" notion: minimal polynomial (`minpoly`), order of a group (`Nat.card G` / `Fintype.card G`), degree, rank — use the dedicated Mathlib definition.

**(P11) Preserve the problem's quantifier order and the placement of negation.**
"For any … there exists … such that …" → universal binders, then an existential target carrying ALL the stated properties. "There exists … such that for all …" → existential outside, universal inside. "Show that P does not imply Q" → `¬ (∀ …, P → Q)` or `∃ …, P ∧ ¬ Q` (see P8). Swapping ∀/∃ or moving a negation changes the meaning → unfaithful.

**(P12) Bind EVERY symbol — dimension indices, parameters, units. `ℝ^k` is not Lean.**
The LaTeX `ℝ^k` has no Lean counterpart; writing `(x y : ℝ^k)` fails with `Unknown identifier k` (autoImplicit is off). Introduce the dimension as a binder and use `EuclideanSpace ℝ (Fin k)`. Correct formalization of the parallelogram identity "for x, y ∈ ℝ^k, |x+y|² + |x−y|² = 2|x|² + 2|y|²":
```lean4
theorem vector_norm_identity (k : ℕ) (x y : EuclideanSpace ℝ (Fin k)) :
    ‖x + y‖ ^ 2 + ‖x - y‖ ^ 2 = 2 * ‖x‖ ^ 2 + 2 * ‖y‖ ^ 2 := by sorry
```
The same applies to ANY letter in the problem: if it is not bound and not a Mathlib constant, the statement does not compile.

**(P13) Imaginary units and special number systems — `𝕚` does not exist.**
- Gaussian integers: type `GaussianInt` (notation `ℤ[i]`), imaginary unit `GaussianInt.i`.
- Complex numbers: type `ℂ`, imaginary unit `Complex.I` (or `I` after `open Complex`).
State divisibility/equality IN the ring the problem names, with explicit numeral casts so the type is unambiguous. Correct formalization of "2 is divisible by (1+i)² in ℤ[i]":
```lean4
theorem two_dvd_one_add_i_sq :
    ((1 : GaussianInt) + GaussianInt.i) ^ 2 ∣ (2 : GaussianInt) := by sorry
```

**(P14) Subtype domains: match argument types exactly; "unique extension" is `∃!` with agreement inside.**
- `closure A` is a `Set X` (lowercase — `Closure` is an unknown identifier). Functions out of it have domain the subtype `↥(closure A)`; writing `g : closure A → Y` is fine (the coercion is automatic).
- A function `f : A → Y` (i.e. `↥A → Y`) can ONLY be applied to terms of the subtype `↥A` — applying it to a bare `x : X` is an "application type mismatch" error. To say "g extends f", quantify over the SMALLER subtype and coerce into the larger one: `∀ x : A, g ⟨x.1, subset_closure x.2⟩ = f x`.
- "f can be uniquely extended to a continuous g which is uniformly continuous" → ONE `∃!` whose body contains ALL the properties: continuity, uniform continuity, and agreement with f on A.
- "let Y be complete" → instance binder `[CompleteSpace Y]`; "uniformly continuous" → `UniformContinuous f`.
Correct formalization of the unique-extension theorem:
```lean4
theorem uniform_continuous_extension {X Y : Type*} [MetricSpace X] [MetricSpace Y]
    [CompleteSpace Y] (A : Set X) (f : A → Y) (hf : UniformContinuous f) :
    ∃! g : closure A → Y, Continuous g ∧ UniformContinuous g ∧
      ∀ x : A, g ⟨x.1, subset_closure x.2⟩ = f x := by sorry
```
